# Выбор нескольких регионов каталога

В строке поиска нажмите «Вся Россия» или название выбранного региона. В списке доступны все 85 регионов из существующего справочника проекта. Галочки можно сочетать произвольно: например, выбрать Москву, Московскую и Воронежскую области. Нажмите «Применить» — выдача включает лоты из **любого** выбранного региона.

- «Вся Россия» отмечает все регионы; можно затем убрать отдельные галочки. Все 85 регионов означают отсутствие регионального ограничения.
- Чтобы выбрать несколько регионов с нуля, снимите «Вся Россия» и отметьте нужные. Пока не отмечен ни один регион, кнопка «Применить» недоступна и текущая выдача сохраняется.
- Строка «Найти регион» только сокращает видимый список, сохраняя ранее выбранные галочки.
- Escape, крестик, нажатие вне списка или уход фокуса из списка отменяют неприменённые изменения. Tab перемещает фокус; Space переключает галочку; Enter в строке поиска применяет непустой выбор.
- Применённый набор сохраняется в браузере, восстанавливается после перезагрузки и при возврате из ленты. Общий сброс фильтров возвращает «Вся Россия».
- Регион в шапке и геолокация остаются исходной точкой для расстояний и рекомендаций. Сохранение «Только мой регион» применяет один регион каталога; геолокация сбрасывает ограничение каталога, как раньше.

## Устройство кода

`dist/region-select.js` подключается после `catalog-data.js`, до основного inline-скрипта. `FasRegions` проверяет и нормализует значения по `RF_REGIONS`, предоставляет общий OR-предикат и подпись. `FasRegionSelect` создаёт интерфейс после DOMContentLoaded. `dist/region-select.css` содержит только стили этого элемента.

Единственный применённый источник состояния — существующий `#region-filter.value`: пустая строка означает всю Россию; одиночный код (`36`) совместим со старой версией; несколько кодов хранятся без повторов в стабильном порядке (`36,50,77`). Внутри открытого списка существует временный набор галочек, который не меняет выдачу до подтверждения.

Для программного назначения используйте `window.FasSetRegionValue(value)`; функция добавляет необходимый составной option в скрытый select. Затем вызовите его обычное событие change либо существующий путь syncSearchFields/render. Нельзя присваивать многозначную строку нативному select без соответствующего option: браузер превратит её в пустое значение. Старые прямые назначения пустой строки/одного существующего кода остаются совместимыми.

Основной render, города, предварительная подготовка поиска, сохранённый поиск и уведомления подписок используют общий `regionMatches`. `app-ui.js` сохраняет тот же scalar в прежнем `fas-search-preferences-v1`; лимит чтения региона увеличен до 1024 символов, чтобы набор из 84 регионов не обрезался. Нового отдельного хранилища нет. Повреждённый набор не расширяет результаты до всей страны: обозначается как недоступный и не даёт совпадений.

Подписка, созданная из текущего поиска, сохраняет точный набор регионов через составной пункт старого редактора подписок. Обычный редактор региона продавца и адреса имущества остаётся однозначным.

## Проверки

`node tests/region-multiselect.cjs` проверяет 85 кодов, OR для 3/5/84/всех регионов, города, подготовку текстового запроса, восстановление старой одиночной и новой составной записи, возврат из ленты, сохранённый поиск/подписку, сброс, галочки, недоступность пустого выбора, Escape и внешний сброс открытого списка.

Дополнительно прошли существующие сценарии геолокации, голосовых критериев, подписок, восстановления поиска, подготовки выдачи, городов и ближайших лотов: всего 9 профильных тестовых файлов вместе с новым тестом.

Браузерный QA на ширинах 1366, 390 и 320 пикселей прошёл: выбор 3 → 5 регионов с фактической OR-выдачей, перезагрузка, все 85 → исключение одного (84), сброс, Escape и отмена нажатием вне списка. Ошибок JavaScript нет. Обнаруженное на 320px смещение панели на 1px за левый край исправлено ограничением положения по фактической ширине viewport; повторная проверка прошла. Это автоматизированная проверка браузера с мобильными размерами, а не новый тест на физических телефонах.

Публикация и синхронизация мобильных ресурсов выполняются отдельным шагом после общего прогона.
