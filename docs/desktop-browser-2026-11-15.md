# Правки сайта на компьютере — 15 ноября 2026

## Пользователю

- Верхнюю подборку можно перетаскивать левой кнопкой мыши за карточку, её название или промежуток между карточками. Стрелки и прокрутка тачпадом остаются доступны.
- Если начать перетаскивание на фотографии с несколькими кадрами, листается альбом этой карточки. На границе альбома движение не переключается на внешнюю подборку.
- Короткий обычный клик открывает лот. Перетаскивание не должно открывать его случайно. Кнопки избранного и продавца сохраняют свои действия.
- Обычное колёсико над подборкой листает её горизонтально, а над многостраничным фото — альбом. На границе прокрутка страницы остаётся доступной. Горизонтальные жесты тачпада и Ctrl+колёсико для масштаба не перехватываются. У краёв появляются кнопки со стрелками; сами по себе наведение и фокус ничего не прокручивают.
- В верхнем меню убрана ссылка «Торги». «Банкам и менеджерам» переименовано в «Организациям-партнёрам», каталог организаций называется «Организации-партнёры». Фильтр «Банки» внутри каталога продолжает обозначать конкретный тип организации.
- «Разместить» заметнее и крупнее соседних кнопок. Усилены контраст элементов и разница между заголовками, ценами и вспомогательным текстом. На небольших компьютерных экранах меню занимает отдельную строку.
- В личном кабинете навигация расположена слева, содержимое — справа. Здесь кнопка «Разместить объявление» компактная. Для Safari на iPhone пользователь отдельно разрешил такую же перестройку кабинета; остальные мобильные разделы не меняются. Черновики доступны через отдельную вкладку и раскрывающийся список внизу.
- На компьютере клик левой кнопкой по пустому фону вокруг верхнего окна возвращает на предыдущий экран. Клик по фону полноэкранной ленты сворачивает её с короткой анимацией и возвращает в исходную подборку. Защита несохранённых форм, вложенные окна и предыдущая позиция прокрутки сохраняются. При настройке уменьшения движения анимация отключается.

## Категории и персональные подборки

Раньше нажатие на родительскую категорию открывало выбор подкатегорий, но само по себе не применяло фильтр. На компьютере теперь родительский раздел применяется сразу; окно подкатегорий остаётся для уточнения. «Товары для дома», «Недвижимость» и «Электроника» фильтруют и основной каталог, и верхнюю подборку. Выбор категории продавцом и специальные окна с собственным callback сохраняют прежнее поведение.

Все пять desktop-подборок сначала используют часто просматриваемые категории, затем свои условия. «Выгодные» требуют актуальной оценки и скидки; «Дешевле» использует действующую логику ценовой выгодности; «До 24 часов» требует окончания строго раньше чем через сутки. Для «Рядом» выбранная точка помогает сортировать по расстоянию. Несколько одновременно включённых кнопок означают **пересечение** условий, поэтому результат может быть пустым. Это не обещание наличия лотов в каждой подборке.

Без истории просмотров и при отключённой персонализации используется доступный каталог, без записи фиктивной истории. При наличии интересов отсутствие подходящих живых лотов не подменяется посторонней категорией. Явный поисковый запрос/выбор категории сохраняет приоритет одиночной подборки; сочетания продолжают пересекать условия. «Вся лента» сохраняет выбранные условия за пределами краткой верхней подборки.

## Граница изменения

Новый вид включается при ширине от 1025 CSS-пикселей, указателе fine и поддержке hover. Телефонные браузеры, Android/iPhone/iPad, iPad с desktop user-agent и оболочки Capacitor исключены. При сужении окна подписи и оформление возвращаются к исходным. Сенсорная прокрутка остаётся нативной.

Папка `mobile/`, пакеты Android/iOS, серверная логика, база и пользовательские хранилища этой правкой не изменяются. Исключение из первоначального desktop-only задания — явно запрошенное оформление кабинета в мобильном Safari на iOS. Это не новая сборка приложения. Не запускайте `mobile` sync только ради данной правки.

## Разработчику

- `dist/desktop-web.js`: единая проверка среды `FasDesktopWeb.active()`, класс `html.desktop-web`, обратимое изменение подписей. Содержимое каталога обновляется после его перерисовки. Используется `textContent`, без внедрения HTML.
- `dist/desktop-web.css`: только правила внутри desktop media query с обязательным префиксом `html.desktop-web`; загружается после существующих стилей.
- `dist/featured-lots.js`: обработчик mouse pointer с порогом 8 px и проверкой преимущественно горизонтального движения. Touch и wheel не перехватываются. Завершение через pointerup/cancel, blur и изменение подходящей среды.
- `dist/featured-lots.css`: курсор перетаскивания и временное отключение scroll snap только во время mouse drag.
- `dist/index.html`: подключение desktop-модуля/стилей и новые версии URL ресурсов ленты.
- `dist/category-ui.js`: применение родительской категории при просмотре на компьютере.
- `dist/desktop-dialogs.js/css`: обработчик клика по фону через существующий безопасный маршрут назад и анимация выхода из полной ленты.
- `dist/seller-ui.js`: структурные обёртки кабинета; исходный порядок элементов сохранён для остальных мобильных режимов.
- `dist/cabinet-layout.js/css`: обратимая компоновка кабинета и черновиков для desktop и браузера iOS; существующие узлы форм перемещаются без потери обработчиков/значений.
- `.gitattributes`: единые LF-переносы для текстовых исходников. Это сохраняет контрольные суммы соглашений и модели на Windows; бинарные файлы не преобразуются.

Исходная точка: Sites source `e9646bf9e1fb6058a392fa2ca83836c489010036`, опубликованный интерфейс v66. Работа выполнена в отдельной копии репозитория Sites: прежние незакоммиченные изменения локального GitHub-проекта не перезаписывались и не включались в эту публикацию автоматически.

## Проверка

Целевые проверки: `node tests/featured-desktop-drag.cjs` и существующие `tests/featured-*.cjs`; браузерный прогон `node scripts/diagnostics/desktop-web-checkup.cjs`. Для браузерного прогона требуется доступный Playwright/Chrome; путь задаётся согласно началу скрипта.

Полный набор запускается командой `node scripts/run-regression-suite.cjs`; отчёт задаётся через `FAS_SUITE_REPORT` либо сохраняется в игнорируемый `test-results/full-suite.json`. Запускаются самостоятельные тестовые файлы и три интеграционных адаптера, по два процесса одновременно. Для SQLite-проверок нужен Python; на Windows задайте `PYTHONUTF8=1` и `PYTHONIOENCODING=utf-8`. Проверка WebP использует уже установленные зависимости `mobile/node_modules` и временную junction на Windows, без повторной загрузки пакетов.

Перед публикацией обязательны `node --expose-gc scripts/diagnostics/model-marketplace-100.cjs` и `tests/security-*.cjs` согласно `AGENTS.md`. Модельные участники изолированы и не добавляют данные на сайт. Результаты текущего прогона фиксируются ниже после завершения проверок; старые результаты v66 не заменяют новую проверку. Эмуляция размеров iPhone/Android в Chrome не заменяет проверку Safari на настоящем устройстве.

## Откат

Для отката интерфейса можно развернуть ранее сохранённую версию Sites. Не удаляйте браузерные данные и не сбрасывайте базу: этот выпуск не требует миграции. Сохраняйте текущую аудиторию сайта и историю исходников. Не запускайте сборку мобильных приложений как часть отката desktop-оформления.
