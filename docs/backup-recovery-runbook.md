# ФАС торги: отложенный план резервирования и восстановления

Внешняя активация отложена пользователем. Это план, а не работающий offsite backup или HA. Подробный машинный документ: [backup-recovery-plan.json](backup-recovery-plan.json).

План основан на аудите коммита `3f07a8b6a9752052ca0b60257940ff47db22b886` (v59), до публикации v60. JSON сохраняет исторические размеры/даты артефактов и названия этапов; они не подтверждают наличие текущей резервной копии. Перед реальным восстановлением нужны актуальные схема, commit, артефакты и проверенный экспорт.

## Что можно восстановить

Исходники и встроенные ресурсы Worker восстанавливают интерфейс. Привязка D1 `DB` содержит только `site_users` и `sale_events`: посещения и демонстрационную аналитику. Приватная аудитория и доверенный вход управляются Sites отдельно от локального manifest. Профили, объявления, черновики, демоставки, избранное и фото/видео находятся в localStorage/IndexedDB браузера или WebView; SQL-снимок их не содержит.

Нельзя публично запускать текущий Worker на другом хосте без auth gateway: он доверяет заголовку `oai-authenticated-user-id`, который сейчас добавляет доверенная платформа. Внешний шлюз должен удалять клиентский заголовок и проверять сессию. Для доступа к прежней аналитике должен сохраниться стабильный principal или контролируемое сопоставление идентификаторов.

## Будущий переносимый комплект

1. Финальный проверенный commit выбранного выпуска; исходники, tracked-path manifest и SHA-256 файлов. Меняющаяся рабочая копия не является подтверждённым релизом.
2. `worker/index.js`, `dist` исходники/ресурсы, build/validate scripts, `.openai/hosting.json`, миграции и journal; мобильные проекты/lockfile/адаптер. Токены и закрытые ключи отдельно.
3. Точный собранный Worker и мобильные артефакты — только при подтверждении соответствия commit и хешам. Имеющиеся ZIP/APK ignored Git и сами по себе не резервная инфраструктура.
4. Нативный согласованный экспорт D1, который позже делает владелец через разрешённые инструменты; timestamp/snapshot ID/schema/export hash. Не читать таблицы порциями при продолжающихся записях и называть это согласованным снимком.
5. Шифрование всего комплекта до передачи, например age с заранее предоставленным публичным recipient. Закрытый recovery key хранить отдельно, не в Git/скрипте/чате/том же bucket. Загружать только ciphertext в независимое хранилище с проверкой чтения и retention.

## Проверяемое восстановление

- Проверить checksum ciphertext, расшифровать в закрытой временной среде, сверить manifest; не печатать SQL/ключи.
- Развернуть исходники в изолированном каталоге. Build script использует `git ls-files`: для plain tar создать временный Git index ровно из recorded tracked paths; либо использовать отдельно проверенный Git bundle.
- Выполнить `node scripts/build-worker.mjs` и `node scripts/validate-worker.mjs` на изолированной копии, не меняя Site ID/аудиторию боевого сайта.
- Импортировать D1 SQL в новую тестовую БД; проверить integrity, таблицы/индексы, ограничения, суммарные количества и owner scope. Не импортировать поверх production.
- Подключить доверенную авторизацию и приватную аудиторию до открытия API; проверить отказ гостю и изоляцию двух разных пользователей.
- Проверить интерфейс/ресурсы/PWA и отдельно восстановление пользовательского browser archive, когда такой экспорт будет реализован. Новый origin не видит старый localStorage/IndexedDB.
- Измерить фактический RPO/RTO, записать результаты и порядок failback. Сборка исходников не доказывает восстановление данных/входа.

## Почему это не мгновенный standby

Платформенный `.chatgpt.site` не является управляемым DNS-доменом владельца проекта. Нет независимого хоста, DB replication, storage, auth gateway и балансировщика. Snapshot имеет возраст; hourly backup не даёт RPO=0. Будущий HA требует стабильного собственного домена, независимого контура, общей/реплицируемой идентичности, единственного активного writer с fencing и испытаний failover/failback. Даже DNS TTL не гарантирует мгновенное переключение всех клиентов и сессий.

Автокопирование, расписание, облако, DNS и HA сейчас не подключались; приватные строки D1 не читались и не экспортировались.
