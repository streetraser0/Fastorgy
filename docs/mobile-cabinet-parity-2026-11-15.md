# Одинаковый личный кабинет на iPhone и Android

Дата изменения: 15 ноября 2026 года. Основа — исходники опубликованной версии 67.

По новому запросу пользователя кабинет, ранее включённый для сайта на компьютере и iOS-браузеров, также включён для Android-браузеров и оболочек Capacitor на Android/iOS.

## Что видит пользователь

- Разделы кабинета расположены слева, содержимое выбранного раздела — справа.
- «Мои черновики» — отдельная вкладка слева. В разделе «Мои лоты» черновики находятся в раскрывающемся списке внизу. Это те же объявления, а не дополнительные копии.
- Кнопка «Разместить» остаётся компактной. На телефоне меню занимает 90 px, оставшееся место получает содержимое; от 700 px меню расширяется до 160 px.
- Поля профиля на телефоне имеют размер шрифта 16 px. Кнопки сохранения и входа по SMS остаются в одной вертикальной колонке, включая ширину 320 px.

## Где искать реализацию

- `dist/cabinet-layout.js`: определение режима, классы `cabinet-layout-on` и `mobile-cabinet`, перенос существующей кнопки черновиков и строк объявлений. `ios-cabinet` сохранён как признак iOS для совместимости, но мобильные стили теперь используют общий `mobile-cabinet`.
- `dist/cabinet-layout.css`: общий вид кабинета iOS/Android. Нижний отступ учитывает `safe-area-inset-bottom`, боковые — безопасные области экрана. Существующие верхние отступы мобильного окна и кнопки закрытия остаются в `seller.css`.
- `dist/desktop-web.js` и его условие включения не расширялись. Новый мобильный кабинет не включает десктопную шапку, перетаскивание мышью или обработчики десктопного фона окон.

Мобильный режим определяется по iPhone/iPad/iPod, iPad с представлением Mac, Android либо установленному признаку `native-app`/`Capacitor.isNativePlatform()`. Поздний запуск native bridge также включает общий кабинет. Обновление режима сохраняет сами DOM-элементы формы, обработчики, значения полей и раскрытый список черновиков. Изменений формата хранилища или миграции данных нет.

Модуль наблюдает только контейнер содержимого окна и класс корневого элемента. Каталог и его секундные таймеры не вызывают повторный обход кабинета. Обработка Back, сохранение черновика, отказ при ошибке записи и защита профиля продолжают выполняться прежними модулями; новый модуль не закрывает окна и не вызывает историю браузера.

## Проверка и выпуск

Локальные проверки:

```text
node tests/desktop-cabinet-layout.cjs
node --test --test-concurrency=1 tests/dialog-stack.cjs tests/seller-back-gesture.cjs tests/dialog-blank-back.cjs
```

Для этой правки прошли 25 проверок раскладки и 3 связанных файла проверок Back/вложенных окон/защиты форм. Проверка синтаксиса `node --check dist/cabinet-layout.js` и `git diff --check` также завершились успешно. Это результаты локальных тестов, а не подтверждение запуска на физическом телефоне.

Браузерная проверка перед выпуском должна охватывать Android/iPhone на 320–412 px, планшет и имитацию native bridge: открытие кабинета, вкладку черновиков, раскрытие списка, редактирование, несохранённый профиль, вложенное окно и возврат. Проверка в Chromium с мобильными параметрами не заменяет запуск в Safari/WebView на физическом устройстве.

Для установленного приложения изменения появятся только после подготовки веб-ресурсов и выпуска новой Android/iOS-сборки. Изменение опубликованного сайта само по себе не обновляет содержимое ранее установленного APK/IPA. Подготовка и проверка таких сборок относятся к общему процессу выпуска и не выполняются модулем кабинета.
