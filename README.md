# ФАС торги — начало работы с проектом

Сайт аукционов имущества: каталог, поиск, лента, карта и личный кабинет. Веб-версия, PWA и приложения Capacitor используют общий интерфейс из `dist/`.

**Сейчас это демонстрационная система.** Каталог содержит демолоты; пользовательские объявления, ставки, профиль и файлы в основном хранятся на устройстве. Сервер обслуживает статистику, но ещё не проводит общие торги, подтверждённую регистрацию и денежные расчёты. Выбранный для будущего подключения банк — **Т-Банк**. Открытие формы оплаты не списывает деньги.

Опубликована **v66** (14.11.2026, 22:59:49 UTC), исходники `3cc311493099a9eeae086b139efb2f26f393fe9c`: [подтверждение](docs/publication-66-2026-11-14.json). Пройден полный набор **209/209 файлов за 388,29 с** на неизменённом снимке; CSP и статистика отдельно повторены после ограничений среды, первичная попытка и повторы сохранены в аудите; **1110/1110 мобильных сверок**, три изолированных провайдерских теста, штатные 100 моделей и 10 security-файлов перед push, 22 контрольных read-only HTTP-запроса. ## Версия 63: голос и возврат

Следующие изменения **опубликованы в v63**. Настройки находятся в **«Кабинет → Профиль → Голосовой помощник → Настроить»**; микрофон сразу открывает компактное прослушивание. Разрешение на запись запрашивает браузер. Настройки открываются над профилем, сохраняя введённые поля и прокрутку.

Полноэкранная лента закрывается свайпом влево/вправо вне галереи и потягиванием вниз с первого лота от настоящей верхней границы, в том числе с фотографии. В кабинете работают горизонтальные свайпы по свободной области и потягивание вниз от верха. Листание фотографий, нативная прокрутка и защита незавершённых форм сохраняются. Возле телефона внизу сайта добавлена отдельная ссылка на пользовательское соглашение.

На неизменённом коде прошли **55 целевых проверок**: [отчёт](docs/feed-voice-audit-2026-11-14.md). В момент выпуска v63 в репозитории было **203 тестовых файла**; результат 55 проверок не означает полный прогон всех 203. Физические Safari, микрофон и жесты требуют отдельной проверки на устройстве.

## Версия 65: нативное листание фотографий

Нативный вариант **опубликован в v65**. Фотографии внутри карточки верхней ленты прокручиваются нативным браузерным контейнером и двигаются вслед за пальцем. Стрелки поверх фото и прежний шаг по завершению касания убраны. Свайп вне фото прокручивает лоты; единственный снимок сохраняет обычную внешнюю прокрутку. Внизу — ровно одна точка на фотографию, включая единственное фото; активная точка плавно меняется, при системном уменьшении движения анимация отключается. С клавиатуры ←/→ управляют той каруселью, в которой находится фокус.

Сначала запрашивается один выбранный снимок на карточку; соседние кадры подготавливаются после взаимодействия, остальные — по мере прокрутки. Выбор сохраняется по URL. Обновление только цены не пересоздаёт фотоконтейнер и не сбрасывает его дробную позицию; изменение размера и возврат из скрытого состояния восстанавливают выбранный снимок. Демо-фрагменты имеют разрешённое кадрирование и подписи. [Отчёт v65](docs/featured-native-carousel-audit-2026-11-14.md) фиксирует отдельный проверенный снимок. Текущее число файлов `tests/*.cjs` вычисляется командой ниже; добавление файла не означает завершённый полный прогон. Физический Safari и фактическая RAM телефона не измерялись: подключённых устройств/эмуляторов — ноль.

## Подготовка уведомлений Telegram и MAX

Отключённые серверные адаптеры подготовлены в v65 отдельно в `integrations/telegram/` и `integrations/max/`: [Telegram](docs/telegram-integration.md), [MAX](docs/max-integration.md). Боты ещё не созданы и не подключены к аккаунтам сайта; настоящего адреса или QR-кода пока нет. Планируются собственные ставки/лоты и подборки по сохранённым подпискам, явное подключение и отключение уведомлений. Подготовленный адаптер не запускает рассылку и не превращает локальный профиль в подтверждённую серверную учётную запись. Название и изображение берутся из бренда сайта; доступность адреса проверяется при реальном создании бота.

## Версия 66: локальные сценарии и ограничения

В v66 опубликованы **«Кабинет → Сообщения»** и **«Написать продавцу»** в лоте: это [локальные черновики](docs/messages.md), без настоящей отправки, прочтения или фиктивных непрочитанных. [Оформление витрины](docs/seller-branding.md) меняет только декоративную шапку собственного частного профиля на устройстве; канонический продавец сохраняется, организациям нужны будущие проверенные полномочия. [«Банки и партнёры»](docs/bank-following.md) — публичный каталог банков/лизинга/партнёров по доступным лотам и локальные подписки, без настоящей рассылки.

[Бесплатные квоты](docs/listing-quota-policy.md): 3 легковых автомобиля, 2 объекта недвижимости суммарно, 1 готовый бизнес одновременно, включая запланированные публикации. Техника/оборудование не получают лимит готового бизнеса. В демоинтерфейсе v66 UI проверяет публикацию/возобновление, а общий планировщик — автоповтор; при отказе сохраняется черновик, прежние защищённые торги не удаляются. Это локальная проверка, не доверенный биллинг/общая БД. Числа платных квот не утверждены, организационные 1000 — только неактивный договорный пример.

В опубликованной v66 соглашение — **2026-11-14-r2**, 13 разделов и [11 страниц PDF](docs/legal/user-agreement-2026-11-14-r2.pdf); r1 и история согласий сохранены. Актуальное принятие требуется перед соответствующим действием, включая публикацию. [Передача прав и ограничения](docs/copyright-handover.md) и [памятка по практике ВС](docs/legal/supreme-court-ip-review-2026-11-14.md) объясняют нейтральный текст подвала без выдуманного перехода всех прав к ООО.

[Проверка производительности проекта](docs/project-performance-review-2026-11-14.md) воспроизводит две локальные оптимизации: повторный поиск лота в сообщениях и ненужные полные массивы при неактивном автоповторе. Это не измерение RAM/FPS на iPhone. У владельца Windows и iPhone, удалённого моста нет; сейчас ручная настройка устройства не требуется, фактические измерения остаются неподтверждёнными.

## Первая проверка после получения исходников

Нужны Git, Node.js 22+ и Python 3. Часть серверных тестов вызывает именно команду `python`; она должна запускать Python 3 со стандартным модулем `sqlite3`. Для обычных клиентских тестов установка npm-пакетов не требуется. Команды выполняются из корня репозитория:

```sh
git status --short
node --version
python --version
node tests/category-tree.cjs
node tests/live-auction-price.cjs
node tests/cross-tab-auctions.cjs
node tests/payment-ui.cjs
```

Полный набор:

```sh
for test_file in tests/*.cjs; do
  node "$test_file" || exit "$?"
done
```

Это исполняемые проверки с моделируемым DOM/хранилищем и локальной SQLite. Физические жесты, микрофон, камера и геометрия Safari требуют отдельной проверки на устройствах.

## Какие файлы менять

| Задача | Исходники |
| --- | --- |
| Каталог, текущая цена, центральная навигация и обработчики ставок | `dist/index.html` |
| Поиск и категории | `dist/search-intent.js`, `dist/keyword-search.js`, `dist/category-tree.js`, `dist/category-ui.js` |
| Кабинет и размещение | `dist/seller-ui.js`, `dist/seller-rules.js`, `dist/seller-media.js` |
| Микрофон и настройки помощника | `dist/voice-assistant.js`, `dist/voice-assistant.css`, `dist/assistant-personalization.js`, `dist/assistant-preferences.js`; вход из профиля в `dist/seller-ui.js` |
| Лента, карта, фото и жесты | `dist/featured-lots.js`, `dist/property-map.js`, `dist/lot-photo-viewer.js`, модули жестов |
| Сообщения, оформление и подписки | `dist/messages.js`, `dist/seller-branding.js`, `dist/seller-following.js`; локальные демонстрационные сценарии |

| Нативные адаптеры | `mobile/scripts/native-bridge.js`, настройки Android/iOS |

Несмотря на название, `dist/` здесь содержит **редактируемые веб-исходники**, а не только сборку. Не исправляйте вручную `dist/server/`, `dist/.openai/`, `mobile/www/` и скопированные web-ресурсы Android/iOS: они генерируются из исходников.

## Сборка сайта

Корневого `package.json` и команды `npm start` нет. Сборщик Worker использует стандартные модули Node.js:

```sh
node scripts/build-worker.mjs
node scripts/validate-worker.mjs
```

Число ресурсов считается динамически по отслеживаемым публичным файлам: в проверенной v66 их 269, но для следующих изменений это не неизменная константа. Перед сборкой новые публичные файлы должны быть добавлены в Git: сборщик берёт список ресурсов из `git ls-files dist`. Сборка создаёт `dist/server/index.js`, CSP и копию миграций; она сама по себе ничего не публикует. Порядок безопасной публикации описан в [руководстве](docs/developer-handover.md#публикация-и-откат).

## Мобильная сборка

```sh
cd mobile
npm ci
npm run sync
npm run check
```

Android дополнительно требует JDK 21 и Android SDK 36. Подписанная iOS-сборка требует macOS, Xcode и аккаунта Apple Developer. Подробности и ограничения — в [mobile/README.md](mobile/README.md).

## Сверка перед передачей

После staging новых публичных ресурсов, сборки Worker и синхронизации/сборки Android:

```sh
python3 mobile/scripts/verify-artifacts.py
```

После коммита исходников экспортируйте согласованный allowlist, обязательно включая `README.md`, и проверьте точный снимок:

```sh
git archive --format=zip --prefix=fas-torgi/ -o releases/fas-torgi-mobile-source.zip HEAD README.md AGENTS.md dist mobile tests REVIEW.md worker scripts drizzle docs integrations reports .gitignore .openai/hosting.json releases/.gitignore
python3 scripts/verify-source-archive.py HEAD releases/fas-torgi-mobile-source.zip
```

Обе проверки сохранены в репозитории, определяют пути от собственного расположения и пишут отчёты во временный каталог ОС. Проверка мобильных ресурсов использует текущий отслеживаемый набор, не жёсткое число файлов. Результаты конкретного выпуска v66 сохранены в подтверждении публикации и общем аудите. Для следующего изменённого снимка проверки выполняются заново; старые результаты его не подтверждают.

## Перед первой отправкой изменений

Проверьте `git config --get core.hooksPath`. Если отдельный путь хуков не настроен, установите проектный:

```sh
git config core.hooksPath scripts/git-hooks
```

Если уже используются другие хуки, сохраните их и подключите проверку проекта к существующему процессу. Не обходите её. При изменении кода pre-push запускает 100 изолированных моделей и проверки безопасности; изменение кода во время прогона блокирует отправку. Расписаний и внешних уведомлений нет.

Секреты, банковские ключи, OTP и персональные выгрузки не должны попадать в Git, браузерный код, архив исходников или журналы.
