# Проверка производительности всего проекта — 14 ноября 2026

Проверка выполнена по запросу владельца: скорость, сохранение контекста и понятность кода относятся ко всему проекту. Рассмотрены текущие каталог/поиск, повторяющиеся обработчики, галереи, сохранение данных, текущие кеши и новый модуль сообщений. Проверены существующие тесты производительности; найденные причины воспроизведены на реальных функциях в локальной Node VM.

Это не измерение физического iPhone/Android, FPS, Core Web Vitals, сетевой задержки пользователя или одновременной нагрузки. Устройства недоступны: [отдельный отчёт по памяти](device-memory-audit-2026-11-14.md). Ни производство, ни внешние сервисы нагрузкой не проверялись.

## 1. Повторный поиск лота при изменениях открытой карточки

В `messages.js` наблюдатель изменений карточки вызывал `decorate()`. Функция сначала искала лот через `cars.find()`, а затем замечала, что кнопка «Написать продавцу» уже существует. Изменения таймера или цены могли повторять этот поиск без изменения кнопки.

Воспроизведение: настоящий модуль и интеграционный fixture, каталог 52 870 лотов, выбранный лот последний, кнопка уже добавлена, 100 вызовов `decorate()`.

| Работа | До | После |
| --- | ---: | ---: |
| Вызовы `cars.find()` | 100 | 0 |
| Просмотренные записи каталога | 5 287 000 | 0 |
| Время одного локального опыта Node | около 1 025 мс | около 16,9 мс |

Теперь проверка существующей кнопки предшествует поиску. Новая карточка по-прежнему получает кнопку, а нажатие заново проверяет текущий лот, владельца, продавца и верхнее окно. Нативная форма ставки и фотолента сохраняются.

В `tests/messages.cjs` добавлена регрессия: 100 повторных обновлений не ищут каталог; замена карточки создаёт правильный вход; старый удалённый элемент не открывает чужой диалог. Проверка всего файла прошла. Временные измерительные скрипты: `/tmp/fas-perf-message-repro.cjs`; для сопровождения важен сохранённый тест, не путь временного файла.

## 2. Ненужная копия каталога при проверке повторных торгов

`auction-renewal.js` каждый раз вызывал `lots.map()`, хотя при отсутствии подходящих повторов возвращал исходный массив. Проверка вызывается таймером раз в 15 секунд при видимой странице. Новый массив заполнялся и затем отбрасывался даже при полностью выключенных повторных торгах.

Воспроизведение: настоящий `FasAuctionRenewal.plan`, 52 870 записей с `autoRelist=false`, 100 проверок. Конструктор `Array[Symbol.species]` считал фактические массивы, создаваемые операцией.

| Работа | До | После |
| Проверенные актуальные флаги opt-in | 5 287 000 | 5 287 000 |
| Выделенные и отброшенные полные массивы | 100 | 0 |
| Суммарные ячейки ссылок в этих массивах | 5 287 000 | 0 |

Это суммарная работа за 100 вызовов, **не размер одновременно занятой RAM**. Локальные прогоны заняли около 1 227 и 1 060 мс соответственно; эти одиночные замеры не доказывают процент ускорения на телефоне. Причинно подтверждённое улучшение — отсутствие ненужных полных копий.

Проверка продолжает проходить все актуальные записи. Кеш, который мог бы пропустить изменение ставки, архива или срока, не добавлялся. Массив копируется один раз после прохождения всех условий первым настоящим повтором; несколько повторов используют ту же копию. Исходные лоты, ставки, история и срок сохраняют прежние правила.

В `tests/auction-renewal.cjs` добавлен тест через `Symbol.species`: 20 пустых проверок не создают копий, два допустимых повтора создают ровно одну, исходник и остальные записи не меняются. На опубликованном v65 (`cdcec4f63d2a4f0c6d90a5ddf5d4c457efbdcd52`) этот критерий даёт 20 копий и не проходит; на исправленной функции — 0 и проходит.

Это 11 целевых файлов проверки, не новый полный прогон всех файлов проекта. Общий финальный прогон и публикацию выполняет основной агент после объединения остальных изменений.

Проверенные свойства существующих модулей: коммерческие демопримеры дополняются линейным проходом; неактивный контекст верхней ленты проверяет 12 выбранных лотов вместо всего каталога; повторные scroll-события галереи объединяются в один кадр; неподдерживаемые поисковые запросы не запускают холодную индексацию; валидная подготовка индекса и отмена сохраняются. Эти уже существовавшие улучшения не выдаются за новые исправления данного аудита.

В текущих просмотренных новых модулях каталог продавцов открывается явно и использует подготовленные модели; сообщения после правки больше не ищут каталог на каждом изменении таймера. Подготовка обложек должна оставаться привязанной к явному открытию/выбору файла, а не к глобальным изменениям DOM. Для каждого нового интегрированного модуля окончательные проверки остаются частью общего выпуска.

## Для сопровождения

- В частых DOM-наблюдателях сначала проверяйте, нужна ли вообще работа; полную актуальную проверку сохраняйте перед действием.
- В чистых планировщиках не копируйте большую коллекцию до подтверждённого изменения. Проверки ставок и срока не заменяйте слабым кешем.
- Сравнивайте количество операций и сохранение результата. Меньшее время в Node само по себе не равно плавной работе на устройстве.
- Не скрывайте реальные задержки удалением характеристик, истории, контроля доступа или предупреждений о сохранении.
