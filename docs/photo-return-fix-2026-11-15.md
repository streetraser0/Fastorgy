# Возврат из открытой фотографии

## Поведение

На сайте компьютера, в мобильном браузере и в мобильной оболочке завершённое нажатие на свободное поле вокруг открытой фотографии возвращает на предыдущий экран. Если фото открыто из карточки лота, закрывается только слой фотографии: карточка, введённая ставка, положение галереи и ленты остаются на месте.

В просмотрщике при масштабе 100% движение вниз возвращает к карточке. Движение влево показывает следующее фото, вправо — предыдущее. Движение вправо на первом фото возвращает к карточке. Кнопки «Закрыть», стрелки, клавиатура и штатный «Назад» продолжают работать. Увеличенное фото можно перемещать; перемещение, увеличение двумя пальцами и горизонтальное листание не считаются нажатием на свободное поле.

Внутри самой карточки сохранён прежний жест: потянуть фото вниз от верхнего положения карточки, чтобы вернуться к списку/ленте. Возврат из просмотрщика и возврат из карточки — два последовательных действия, чтобы не терять текущий лот.

## Причина и реализация

На доме с ID 100200 браузерная проверка воспроизвела оба дефекта полноэкранного просмотрщика. Вертикальный жест не обрабатывался, а элемент `img` занимал весь экранный контейнер, хотя `object-fit: contain` оставлял свободное поле. Общий обработчик возврата корректно исключал `img` и не мог определить это поле. Свайп по фото внутри самой карточки на текущем DOM работал.

Код исправления — `dist/lot-photo-viewer.js`, CSS — `dist/lot-photo-viewer.css`. Для поля рассчитывается прямоугольник реально отображаемого изображения по naturalWidth/naturalHeight и размерам `img`. Нужны начало и конец одного нажатия в свободном поле, смещение не больше 10 px и отсутствие прокрутки. Правый клик, клавиатурный клик, длительное удержание, движение с фотографии на поле, смена фото/масштаба, выделение текста, второй палец или новый верхний диалог не закрывают просмотрщик.

Сохраняются тот же DOM карточки и снимок scroll позиции; `history.back()` и повторного рендера лота нет. Жесты проверяют верхний слой и идентичность открытого фото. Совместимый клик после завершённого свайпа подавляется, а новое осознанное нажатие работает сразу. При 100% CSS резервирует однопальцевое движение для листания/возврата (`touch-action: pinch-zoom`); после увеличения сохраняется нативное перемещение по обеим осям.

## Проверки и ограничения

`node tests/lot-photo-viewer.cjs` покрывает landscape/portrait поля, mouse/touch/старый touch-only путь, защиту от drag/zoom/scroll/multitouch, возврат только верхнего слоя, сохранение DOM и прокрутки, листание и подавление лишнего клика. `node tests/photo-viewer-warm.cjs` проверяет прежнюю подготовку оригинала и задержку двойного нажатия для избранного.

Локальный регрессионный прогон: **11 из 11 файлов прошли** — `lot-photo-viewer`, `photo-viewer-warm`, `lot-touch-semantics`, `lot-close-return-routes`, `map-lot-return`, `seller-storefront-return-routes`, `dialog-journey-regressions`, `dialog-media`, `dialog-stack`, `back-swipe`, `dialog-blank-back`. Проверка синтаксиса и `git diff --check` также прошли.

На реальном Chrome с эмуляцией касаний и шириной 390 px проверены исходный жест карточки дома, возврат из полноэкранного фото и нажатие на поле. Независимый браузерный прогон прошёл **2/2 сценария, без ошибок JavaScript**: Android 390 px — листание, предыдущее фото, возврат с первого фото/свайпом вниз, панорамирование при 150% без закрытия и поле портретного изображения; desktop 1366 px — клик внутри фото, drag с фото на поле, правый клик, Escape и обычный клик на поле. Портретная геометрия дополнительно проверена изолированной тестовой картинкой, без изменения опубликованных лотов.

Это браузерная проверка, а не проверка на физическом iPhone или Android. Мобильные приложения получают исправление после подготовки и установки нового APK/IPA; старые установленные сборки не обновляются изменением сайта.
