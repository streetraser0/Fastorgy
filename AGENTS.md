# Проверки перед публикацией

Пользователь требует запускать диагностику при изменении кода. Повторных прогонов без изменения кода и уведомлений по расписанию не нужно.

- Сохраняйте штатный pre-push hook из `scripts/git-hooks/pre-push`. Если свой `core.hooksPath` уже настроен, не заменяйте чужие хуки: сохраните их и выполните нашу проверку отдельно.
- Перед публикацией изменённого кода выполняйте подходящие регрессионные проверки, прогон `node --expose-gc scripts/diagnostics/model-marketplace-100.cjs` и проверки `tests/security-*.cjs`. Устраняйте подтверждённые причины отказа, не отключайте проверку ради отправки.
- Сто модельных участников работают только в изолированных VM-хранилищах. Не добавляйте фиктивных покупателей, ставок, продаж или счётчиков в опубликованный сайт.
- Не меняйте аудиторию сайта без явного указания пользователя. Не записывайте токены в файлы, исходники, Git или журналы.
- Сохраняйте защиту несохранённых форм, нативную прокрутку, просмотр/масштаб фото и возврат только из верхнего окна.
- Не выдавайте клиентскую демоверсию за защищённую систему реальных торгов: общие серверные роли, подтверждённый вход и денежные расчёты ещё не подключены. Проверки не доказывают отсутствие всех уязвимостей.
